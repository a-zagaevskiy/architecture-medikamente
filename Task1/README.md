# Анализ безопасности системы

## Проблемные зоны

* Отсутствие разграничения доступа до данных в системе. Любой сотрудник имеет возможность просмотреть и изменить любые данные в системе.
* Не ведется аудит (журнал действий сотрудников над данными в системе)
* Нет защиты конфиденциальных данных. Как в общем-то и других данных в системе.
* Ручной ввод данных сильнее подвержен ошибкам.
* Нет контроля корректности вводимых данных.
* Невозможно предоставить доступ пациентов к своим данным в такой системе (результаты анализов, договора, согласия, записи на прием и т.д.)

## Данные для защиты

Персональные данные пациентов - шифрование в местах хранения, обфускация (токенизация) при передаче в лабораторию, обезличивание при составлении аналитических отчетов, тегирование.

Медицинская документация, анализы - шифрование в местах хранения, тегирование, доступ по RBAC.

Финансовые данные - шифрование в местах хранения, обфускация (токенизация), доступ по RBAC.

## Тегирование данных

Классификация по типу данных:
* `PII` - персональные данные
* `PHI` - медицинские данные
* `financial_data` - финансовые данные
* `sensitive_data` - прочие конфиденциальные данные

Классификация по источнику:
* `doctor` - врачебные записи
* `admin` - данные от работников ресепшена
* `lab` - данные из лаборатории
* `patient` - данные от пациента
